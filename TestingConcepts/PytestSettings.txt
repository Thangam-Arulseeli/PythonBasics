What is a fixture?
---------------------

Imagine you have 20 tests.

Every test needs an employee:

employee = Employee(
    "Arun",
    "arun@gmail.com",
    50000
)

You don't want to create this employee manually in every test.

Without fixture:


def test_salary():
    employee = Employee("Arun", "arun@gmail.com", 50000)
    ...


def test_email():
    employee = Employee("Arun", "arun@gmail.com", 50000)
    ...


def test_name():
    employee = Employee("Arun", "arun@gmail.com", 50000)
    ...

Lots of duplication.

A fixture provides reusable test data/setup.


Basic fixture
-----------------
Create:
----------
test_employee.py
----------------
import pytest

class Employee:

    def __init__(self, name, email, salary):
        self.name = name
        self.email = email
        self.salary = salary


@pytest.fixture
def employee():

    return Employee(
        "Arun",
        "arun@gmail.com",
        50000
    )

Now use the fixture in tests:
-------------------------------
def test_employee_name(employee):

    assert employee.name == "Arun"


def test_employee_email(employee):

    assert employee.email == "arun@gmail.com"


def test_employee_salary(employee):

    assert employee.salary == 50000


Notice this
-----------
def test_employee_name(employee):

Pytest sees the parameter: Pytest sees the parameter:    employee


and looks for a fixture named:  
@pytest.fixture
def employee():

It automatically executes the fixture and passes the returned object into the test.


Fixture execution flow

The flow is:

test_employee_name(employee)
            │
            ▼
      pytest searches
      for fixture
            │
            ▼
@pytest.fixture
def employee():
            │
            ▼
 Employee(...)
            │
            ▼
       returns object
            │
            ▼
 test receives employee
            │
            ▼
 assert employee.name == "Arun"

This is one of the most important concepts to understand.


Practical project example

Let's create a proper structure:

PythonBasics/
│
├── employee.py
│

# -------------------------------------------------------

employee.py
class Employee:

    def __init__(self, name, email, salary):
        self.name = name
        self.email = email
        self.salary = salary

    def calculate_bonus(self):
        return self.salary * 0.10

    def is_high_earner(self):
        return self.salary >= 50000

# ------------------------------------------------------------------

conftest.py
Fixtures that need to be shared across multiple test files are commonly placed in conftest.py.

import pytest

from employee import Employee


@pytest.fixture
def employee():

    return Employee(
        "Arun",
        "arun@gmail.com",
        50000
    )



test_employee.py
def test_employee_name(employee):

    assert employee.name == "Arun"


def test_employee_email(employee):

    assert employee.email == "arun@gmail.com"


def test_employee_salary(employee):

    assert employee.salary == 50000


def test_employee_bonus(employee):

    assert employee.calculate_bonus() == 5000


def test_high_earner(employee):

    assert employee.is_high_earner() is True



python -m pytest -v

Pytest automatically finds the fixture in conftest.py.

Fixture with setup and teardown

Fixtures become much more useful when testing databases.

For example:

@pytest.fixture
def employee():

    print("Creating employee")

    employee = Employee(
        "Arun",
        "arun@gmail.com",
        50000
    )

    yield employee

    print("Cleaning up employee")
